40 corrected MIPS tests

No infinite ending jumps. All executed control transfers are counted.

What changed

Every ending done: j done has been removed and replaced with a harmless addi $zero, $zero, 0. Test IDs, coverage and final data expectations are preserved. Programs remain 10–15 physical lines each.

Every executed jump now appears in the redirect total. Nothing is excluded. The previous package counted only the body and excluded its infinite ending jumps. This revision removes that distinction.

All 40 corrected programs were assembled with your uploaded Java assembler and run on your latest MIPS(1).circ in Logisim Evolution 4.1.0. Final values, actual stall counts, actual redirect counts and PC updates matched the reference results for every program.

Run each test this way

  1. Disable automatic ticking. Clear the instruction ROM to 0000, then load the assembled program. This removes leftover instructions from previous tests. After the source ends, cleared ROM words decode as sll $zero, $zero, 0, which has no data side effects.
  2. Reset the CPU: PC = 0, pipeline registers = 0, $t0…$t4 = 0, $zero = 0, $sp = 15. Start with clock low. Each test is independent.
  3. Run exactly 100 complete clock cycles and stop. A full cycle is one rising edge followed by one falling edge: 200 half-cycle transitions. These programs do not halt automatically. Do not keep running until the eight-bit PC wraps and executes the program again.
  4. Compare final registers and specified RAM locations. RAM need not be preloaded: every load reads a value its test has already stored. Unchanged means preserve the cell’s initial value, not necessarily zero. Initial $sp = 15 does not put 15 into MEM[15].
  5. Count stalls and redirects over all 100 cycles. There is no ending loop to subtract. In this setup all test work finishes before cycle 42; remaining cleared-ROM instructions have no stalls, redirects or data side effects.

How counts and values are defined

All values and addresses are decimal in this HTML and the CSV. Decimal 12 = hex C, 14 = hex E, 15 = hex F. PC values are instruction-word addresses starting at zero.

One stall means one rising edge at which the data-hazard signal holds PC/IF-ID and inserts an EX bubble. Two conflicting operands do not count twice. Filling/draining the pipeline and flushing a wrong-path instruction are not data stalls. The split columns distinguish load-use stalls from stalls of a branch waiting for data.

One redirect means one executed j or one resolved, taken beq/bneq. A branch held in ID is not counted until it resolves. Not-taken branches and flushed jumps do not redirect. Even a taken transfer whose target is the next instruction counts once: it still uses the redirect/flush path.

Branches/jumps resolve in ID with no architectural delay slot. Adjacent load-to-store data uses MEM-to-MEM forwarding without a stall; a loaded store base needs one stall. An adjacent ALU-to-branch dependency needs one stall; an adjacent load-to-branch dependency needs two. These counts were measured on your circuit, not just inferred from instruction names.

Arithmetic wraps to four bits. Memory uses an unsigned register base plus a signed four-bit offset. Logical shifts use the full four-bit shift amount; a shift by 4 or more gives zero. Stack and ordinary loads/stores share RAM.

Tests 33, 34 and 39 intentionally contain finite loops to test backward transfers and repeated hazards. Each runs three iterations and exits. All other tests are acyclic.
